# 학생 진도 관리

## 반 교재 관리

진도 관리 제목 옆의 `교재 관리` 버튼을 누르면 창이 열린다. 관리할 반을 선택하고 교재를 추가·편집·삭제할 수 있다. 교재 등록에는 교재명, 총 페이지 수, 단원 목차를 입력한다. 출판사·발행 연도 입력은 없다.

단원 목차는 직접 입력하거나 `math-unit-catalog.md`에서 생성한 27개 템플릿을 사용할 수 있다. 템플릿의 학년은 목차를 불러오는 기준이며 학생 학년을 제한하지 않는다. `node scripts/build-progress-templates.mjs`로 템플릿을 재생성한다.

교재는 반 목록에 등록한 뒤 학생 행의 교재 선택 또는 일괄 교재 적용으로 연결한다. 같은 교재를 여러 학생에게 연결해도 학생별 진도는 독립적으로 저장한다. 교재 편집은 연결된 학생의 교재명·목차·총 페이지에 반영된다. 이름과 상위 단원이 그대로인 학습 항목은 ID와 상태를 유지하며 새 학습 항목은 미시작으로 표시된다. 삭제한 교재는 목록과 학생별 활성 교재에서 제외하되 수업 이력은 보존한다.

## 개별·일괄 편집

왼쪽에서 반을 체크하면 소속 학생 전원을, 학생을 체크하면 해당 학생들을 표시한다. 두 명 이상 선택하면 일괄 편집 패널을 제공한다.

- 교재: 반 교재를 선택해 체크한 학생들에게 연결한다. 다른 반 학생에게 연결하려고 하면 전체 작업을 거부한다.
- 단원: `단원 일괄 관리` 창에서 상태와 완료 페이지를 설정한다. 동일한 목차·총 페이지의 교재를 사용하는 학생들에게 적용한다.
- 진행 범위·숙제: 각각 내용을 입력하고 적용 버튼을 눌러 선택한 학생의 입력란에 반영한다. 빈 값을 적용하면 입력 내용을 비울 수 있다.
- 완료 페이지: 등록한 총 페이지 범위 안에서 일괄 적용한다.

학생 행의 `단원 관리`도 별도 창으로 열리며 그 학생만 수정한다. 단원 상태나 일괄 입력을 적용한 뒤 상단의 `수업 기록 저장`을 눌러 저장한다. 교재 연결은 적용 시 별도로 저장된다.

상단에 날짜와 저장 버튼을 하나씩 제공한다. 작성한 모든 학생의 기록을 공통 날짜로 일괄 저장하며, 하나라도 충돌하거나 실패하면 전체 수업 기록을 취소한다. 작성 중인 학생은 선택을 해제해도 저장·취소까지 표에 유지된다. 실패 시 입력 내용도 유지된다.

## 진행률·이력

- 총 페이지가 있으면 `완료 페이지 수 / 총 페이지 수 × 100`으로 진행률을 계산한다. 완료 페이지는 직접 입력하며 자유 텍스트의 페이지 범위를 자동 해석하지 않는다.
- 총 페이지가 없는 기존 교재는 완료한 소단원 수의 비율을 사용한다.
- 단원 상태는 미시작 / 진행 중 / 완료다. 페이지 진도와 단원 상태는 각각 관리한다.
- `기록 보기` 창은 수업 날짜, 범위, 숙제와 저장 당시 진행률을 표시한다.
- 저장할 때 목차, 총 페이지, 완료 페이지와 상태를 함께 보존한다. 교재가 바뀌어도 이전 기록의 진행률은 변하지 않는다.
- 과거 수업 날짜로 입력해도 저장 당시 상태를 기록한다. 과거 상태를 자동으로 역산하지 않는다.
- 기존 출결·숙제의 O/△/X와 내준 숙제를 자동 연결하지 않는다. 기존 보고서는 변경하지 않는다.

## 저장 구조·적용

로컬 개발에서는 `cosmath-local-v1` IndexedDB 버전 6을 사용한다. 기존 학생별 교재는 반 교재 목록에 연결하며 기존 데이터는 보존한다.

Supabase에서는 다음 마이그레이션을 순서대로 적용한다. 이미 적용한 파일은 다시 실행하지 않는다.

1. `202610130001_student_progress.sql`: 학생 교재·수업 기록
2. `202610130002_progress_book_batch.sql`: 교재 일괄 등록
3. `202610130003_progress_record_batch.sql`: 수업 기록 일괄 저장
4. `202610130004_class_textbooks.sql`: 반 교재 목록, 페이지 진도, 목차·페이지 이력

`cosmath_class_books`는 반별 공용 교재를, `cosmath_progress_books`는 학생별 교재·최신 진도를, `cosmath_progress_entries`는 수업 기록과 저장 당시 스냅샷을 저장한다. 학원별 RLS, 복합 외래키, 버전 충돌 검사와 트랜잭션을 적용한다.

운영 DB에는 자동 적용하지 않았다. 반 교재 삭제는 보관 처리다. 학생을 영구 삭제하면 그 학생의 수업 이력도 기존 삭제 정책에 따라 삭제된다.
